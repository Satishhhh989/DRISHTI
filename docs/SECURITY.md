# DRISHTI Security & Privacy Architecture

**Product Identity**: DRISHTI Engine, DRISHTI Studio, DRISHTI Scene, DRISHTI Motion  
**Version**: `1.0.0` (Production Release)  
**Security Posture**: Production-Hardened, Local-First, Zero-Trust Input Pipeline  

---

## 1. Core Security & Privacy Principles

DRISHTI is architected around absolute **data sovereignty and local-first execution**:

1. **Zero External Data Exfiltration**: Photographs, intermediate neural tensors, 3D polygon meshes, and project databases are processed and stored exclusively on the user's local disk. No image data is ever transmitted to cloud APIs, remote inference endpoints, or telemetry collectors.
2. **Strict Loopback Binding**: The backend REST API binds strictly to `127.0.0.1` (IPv4 loopback) by default. It does not bind to `0.0.0.0` or expose public network interfaces.
3. **Defense-in-Depth Input Validation**: Every untrusted input—whether an uploaded image file, an imported project ZIP archive, or a JSON transform patch—is validated, sanitized, and constrained before reaching downstream compute or persistence layers.

## 2. Input Validation & Image Ingestion Hardening

All user-submitted photographs pass through a multi-tier validation gateway (`services/api/app/pipeline/image_validator.py`):

```
Uploaded File Bytes
         │
         ▼
[Tier 1: Byte-Length Inspection]
   ├── File length > 0 bytes (rejects empty uploads)
   └── File length ≤ MAX_UPLOAD_SIZE_MB (default 25 MB)
         │
         ▼
[Tier 2: Magic Byte & MIME Validation]
   └── Whitelisted MIME types: image/jpeg, image/png, image/webp
         │
         ▼
[Tier 3: Structural Pillow Integrity Verification]
   ├── Image.open(io.BytesIO(buffer))
   ├── img.verify() — verifies internal container checksums and chunk tables
   └── Rejects corrupted headers and truncated bitstreams
         │
         ▼
[Tier 4: Decompression Bomb & Dimension Bounding]
   ├── PIL.Image.MAX_IMAGE_PIXELS = 25,000,000 (25 Megapixels)
   ├── Dimension checks: width ≤ 8192 px, height ≤ 8192 px
   └── Total pixels: (width * height) ≤ 25,000,000
         │
         ▼
[Tier 5: Multi-Frame & Animation Rejection]
   └── getattr(img, "is_animated", False) — rejects animated GIFs, APNGs, and animated WEBPs
         │
         ▼
[Tier 6: EXIF Orientation Normalization]
   └── pillow_heif / ImageOps.exif_transpose() — normalizes EXIF orientation to top-left
         │
         ▼
[Sanitized 8-bit RGB Image Buffer]
```

## 3. Archive Import & Anti-Zip-Slip Defense

DRISHTI supports importing self-contained project archives (`.zip`). Because untrusted ZIP files present severe security risks (arbitrary file overwrite via directory traversal and decompression bombs), DRISHTI enforces strict security checks in `services/api/app/export/engine.py`:

### 3.1 Anti-Zip-Slip Path Traversal Protection
Every entry in an imported ZIP archive is inspected before extraction:
- **Path Component Inspection**: Every entry name is parsed into its path components via `pathlib.Path(entry.filename).parts`.
- **Traversal Rejection**: Any entry containing `..` (parent directory traversal) or starting with `/` or `\` (absolute root paths) is immediately rejected with a `400 Bad Request` security violation.
- **Drive Prefix Rejection**: Any entry containing Windows drive letters (e.g. `C:`) is immediately rejected.
- **Extraction Confinement**: All extracted files are guaranteed to resolve strictly inside a freshly generated, isolated temporary directory (`tempfile.mkdtemp()`).

### 3.2 Anti-Zip-Bomb Resource Limits
Untrusted archives could be engineered to exhaust host memory or disk space:
- **Maximum Archive Entries**: Capped at `MAX_ARCHIVE_ENTRIES = 250` files per archive.
- **Maximum Total Uncompressed Size**: Capped at `MAX_UNCOMPRESSED_BYTES = 500 MB` across all entries.
- **Maximum Individual File Size**: Capped at `MAX_INDIVIDUAL_ENTRY_BYTES = 100 MB`.
- **Compression Ratio Check**: Rejects any file where `file_size / compress_size > 100` (ratio exceeding $100\times$).

## 4. Local File Storage & Isolation

All assets generated by DRISHTI are managed through an explicit storage layer (`services/api/app/assets/storage.py`):

1. **Storage Sandbox**: All writes are confined within the configured `DATA_DIR/storage/` directory.
2. **Identifier Sanitization**: Entity IDs, scene IDs, and filenames are validated against strict alphanumeric and hyphen patterns (`^[a-zA-Z0-9_-]+$`). Slashes and path separators are prohibited.
3. **Atomic File Writes**: All project files (`project.json`) and scene graph definitions (`scene.json`) are written using atomic file swaps:
   ```python
   temp_path = target_path.with_suffix(".tmp")
   with open(temp_path, "w", encoding="utf-8") as f:
       f.write(content)
       f.flush()
       os.fsync(f.fileno())
   temp_path.replace(target_path)
   ```
   This prevents corrupt files resulting from system crashes or sudden termination.

## 5. HTTP Security Headers & Network Boundaries

### 5.1 Enforced HTTP Security Headers
Every HTTP response emitted by the FastAPI backend includes standard defense headers:

```http
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
X-XSS-Protection: 1; mode=block
```

### 5.2 Cross-Origin Resource Sharing (CORS)
CORS is restricted strictly to local browser origins:
```python
CORS_ORIGINS = [
    "http://localhost:3000",
    "http://127.0.0.1:3000"
]
```
Wildcard origins (`*`) and arbitrary public origins are rejected.

## 6. Geometry & Transform Validation

When interacting with the 3D scene or applying user transform edits:
1. **Pydantic Schema Enforcement**: All incoming JSON bodies are validated against strict Pydantic models.
2. **Numerical Range & NaN Checks**:
   - Positions ($X, Y, Z$) are constrained to $[-50.0\text{m}, +50.0\text{m}]$.
   - Rotations are normalized Euler angles.
   - Uniform scale is constrained to $[0.05, 10.0]$ (rejecting zero, negative scales, and non-finite numbers).
3. **Trimesh Geometry Sanitization**:
   - Mesh vertex coordinates are asserted to be finite real numbers.
   - Degenerate faces (zero area) and duplicate vertices are pruned before GLB export.

## 7. Security Verification Suite

DRISHTI includes a dedicated automated security test suite (`services/api/tests/test_security_hardening.py`):

```bash
PYTHONPATH=services/api .venv/bin/pytest services/api/tests/test_security_hardening.py -v
```

Tests include:
- `test_security_headers_present`: Verifies presence of security headers on all responses.
- `test_reject_empty_file_upload`: Rejects zero-byte file payloads.
- `test_reject_excessive_upload_file_size`: Rejects uploads exceeding max size limit.
- `test_reject_decompression_bomb_dimensions`: Rejects malicious image dimensions.
- `test_reject_animated_images`: Rejects animated GIFs and multi-frame formats.
- `test_reject_zip_slip_path_traversal`: Confirms immediate rejection of `../evil.txt` inside archives.
- `test_reject_zip_bomb_excessive_entries`: Confirms rejection of archives with $> 250$ entries.
- `test_reject_zip_bomb_excessive_uncompressed_size`: Confirms rejection of excessive uncompressed sizes.
- `test_cors_headers_loopback`: Verifies CORS rejection of untrusted third-party origins.
